# signal.Vec 自适应后端

`signal.Vec[T]` 是 GX 的响应式数组载体，提供按索引的细粒度订阅：`At(i)` 返回
第 i 个元素的 `Signal[T]`，写它只通知订阅该索引的 effect。

## 自适应策略

按长度自动切换后端，公开 API 与语义完全一致，调用方无感：

| 长度 | 后端 | 结构 | 适用 |
|---|---|---|---|
| ≤ `VecAdaptiveThreshold`(64) | 小后端 | `[]Signal[T]`，每元素一个独立 sig | 细粒度订阅最直接 |
| > 64 | 大后端 | 持久化向量 `pvector.PVector[T]` + 稀疏惰性索引 sig | 大列表省内存、整值结构共享 |

关键机制：

- **稀疏惰性**：大后端只有被 `At(i)` 实际读过的索引才分配 sig，未订阅元素零节点。
- **写入回写**：`At(i)(v)` 直接写入会同步回持久化向量，避免缩容重建时丢值。
- **透明迁移**：Append / SetLen 跨阈值时自动迁移，已建立的订阅不丢失。
- **结构共享**：`pvector` 是 32 叉 trie，`Set` 只复制根→叶一条路径，旧版本可直接当撤销快照（O(1) 内存）。

## 性能对比

测试环境：AMD EPYC 9K65，Linux amd64，Go 1.27。取 `-count=2` 均值。

### 构造 4096 元素列表

| 方案 | 时间 | 内存 | 分配次数 |
|---|---:|---:|---:|
| 旧方案（每元素一个 sig） | 762 µs | 1,310,735 B | 28,673 |
| **自适应大后端** | **338 µs** | **661,586 B** | **4,803** |
| 提升 | **2.3×** | **2.0×** | **6.0×** |

小后端构造 64 元素约 10 µs / 20 KB / 457 allocs（小数据走它，成本可忽略）。

### 大后端热路径（4096 元素）

| 操作 | 时间 | 内存 | 说明 |
|---|---:|---:|---|
| 稀疏读 `At(i%7)()` | ~7 ns | 0 B | 只触及 7 个已物化索引，零分配 |
| 单点写 `Set(i,v)` | ~544 ns | 906 B | trie 路径复制（O(log₃₂ N)） |
| 追加 `Append(v)` | ~133 ns | 204 B | 均摊 O(1) 尾追加 |
| 全量 `Values()` | ~56 µs | 33 KB | 逐项经 `At` 读，订阅语义一致 |

与 `runtime/rope` 的分工：**Rope 管文本缓冲区**（按 rune 索引 + 行列换算），
**pvector 管通用列表**（按下标随机访问）。两者都是不可变、结构共享、单线程，
共同构成 GX 的持久化数据底座。
