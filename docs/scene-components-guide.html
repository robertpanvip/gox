一、书写约定（最先要遵守）

Gox 的设计是：转译器不读第三方包符号表、不做类型推导，只对小写形式做机械首字母大写还原（upperFirst）。因此行为完全可预测。你在 .gx 里写小写，生成的 Go 自动变大写。

五条边界（踩过的坑）：① 所有 signal API 用大写 Signal. 前缀——Signal.computed / Signal.effect / Signal.createRoot / Signal.batch 等。Signal 是语法糖占位包名，既避免与 signal 声明关键字混淆，也保证还原；不要写裸 computed(...) 或小写 signal.effect(...)。 ② 组件名大写开头——pub func Stat(...) 配 <Stat/>。JSX 标签首字母大写 = 组件、小写 = 原生 HTML 标签，这是硬编码判定。 ③ 配置对象写裸字面量、字段小写——gxapp.open({ title: ..., width: ... })，字段写小写（大小写混写、省略可选字段也支持），编译器用 go list + go/parser 读取 gxapp.open 所在包的真实 Go 源码 AST，取出参数类型补全为 gxapp.WindowConfig 并把字段还原成真实拼写（通用机制，对任意外部包函数都有效；读不到时回退匿名 struct）。无需也不应手写 gxapp.windowConfig{...}。 ④ open 与 render 分工——gxapp.open(cfg) 只创建窗口外壳并返回 App，app.render(() => <App/>) 收一个建树函数（SolidJS 风格）：内部建立根 Owner、画首帧、封装 bindReactive（signal 变化 → 更新 + 重绘，含分支/列表结构重绘），源码无需手写接线。组件内的 Signal.effect / onMount / onCleanup 归属该 Owner，app.close 时级联清理。 ⑤ 回调用箭头函数——Signal.computed(() => expr) / Signal.effect(() => ...) / batch / onMount / onCleanup 一律写箭头，贴近 SolidJS 习惯，别写 func() T { return ... }。单语句 () => expr，多语句 () => { stmt; stmt }（花括号 body 生成 func(){...}）；编译器从 body 反推类型，() => count() 单点 signal getter 会从声明类型反查（不降级 any），带参数的 createRoot((o *Signal.owner) => {...}) 保留显式标注。

  func() any { return t() }

③ 更新期（每次写入）

signal 写入

→ effect 重跑
↓
精确写节点

组件是一种「不透明的子树插槽」：骨架编译期固定，组件形状运行时嫁接；更新靠 getter 保鲜 + 递归透传，而不是重建整树或做 vdom Diff。

三、完整实战（一条龙）

下面这段是经过 go run 实测的完整 GX 源码，同时用到了对象字面量、对象解构、signal、条件分支、Keyed For 和应用入口——全部小写写法。

demo.gx · 编译：gox build demo.gx -jsx=scene -o main.go && go run .package main

import (
    gxscene "github.com/robertpanvip/gox/runtime/scene"
    gxapp   "github.com/robertpanvip/gox/runtime/app"
    "github.com/robertpanvip/gox/runtime/signal"
    "fmt"
)

type user struct { id int; name string }

// 叶子组件：pub 小写声明；从 Props 取 getter，在插槽里 value() 读当前值
pub func Stat(props gxscene.Props) *gxscene.Instance {
    label := gxscene.get[string](props, "label")
    value := gxscene.get[int](props, "value")
    return <div class="stat"><span>{label()}</span><b>{value()}</b></div>
}

func main() {
    // 新特性：对象字面量 + 对象解构
    cfg := { title: "Gox", width: 800, height: 600 }
    { title, width } := cfg

    // signal 源 + computed 派生（count 变化 → doubled 自动重算）
    signal count = 0
    signal visible = true
    signal users = []user{{1, "Tom"}, {2, "Jack"}}
    doubled := Signal.computed(() => count * 2)

    // 应用入口：open 只收配置（裸对象字面量）；render 收建树函数，内部建根 Owner + 接线
    app, err := gxapp.open({ title: title, width: width, height: cfg.height })
    if err != nil { panic(err) }
    defer app.close()
    app.render(() => <div id="app">
        <h1>{title}</h1>
        if visible {
            <Stat label="count" value={count}/>
            <ul><For each={users} key={(u) => u.id}>{(u) => <li>{u.name}</li>}</For></ul>
        } else {
            <b>Hidden</b>
        }
    </div>)  // 在根 Owner 下建树 + 内部 bindReactive

    // 批处理：同一帧内 count→5、visible→false，只重绘一次（多语句用花括号 body）
    Signal.batch(() => { count(5); visible(false) })
    fmt.println(doubled)  // 10，signal 读裸写
}
实测输出要点：初始渲染出 "Tom"/"Jack" 列表；visible=false 后条件分支切到 Hidden；doubled() 得到 10。<For> 的 render 参数 (u) 未写类型——编译器从 each={users} 的 []user 自动推断出元素类型。

四、响应式 UI 四阶段增强

阶段 1 · Owner / Cleanup / Effect 句柄

Signal.effect 返回可销毁句柄，挂在 Owner 树下；父 Owner 销毁会级联停掉子计算并执行清理。写副作用时把清理登记在 effect 内，重跑前与销毁时都会执行。

Signal.createRoot((o *Signal.owner) => {
    h := Signal.effect(() => {
        fmt.println(count)
        Signal.onCleanup(() => { /* 重跑前 / 销毁时执行 */ })
        Signal.onMount(() => { /* 首次挂载执行一次 */ })
    })
    _ = h  // h.dispose() 幂等：断依赖、停订阅、执行清理
})
// 相同值不触发下游；自定义比较用 Signal.newWithEquals
// 派生需要提前销毁时用 Signal.computedWithHandle
signal 源信号默认用 reflect.DeepEqual 做相等性裁剪——值未变不触发下游。scene.computation 是 signal.computation 的类型别名，因此 Signal.effect 可作为底层 bindReactive 的实参；应用入口的 app.render 内部已经用 Signal.effect 完成接线，无需手写。

阶段 2 · 条件分支

JSX 内支持 if / else if / else 子节点。selector 读 signal 登记依赖；索引变化时销毁旧 Owner、重建局部子树，索引不变时只更新叶子。

view := <div>
    if visible {
        <span>{count}</span>
    } else if other {
        <i>other</i>
    } else {
        <b>Hidden</b>
    }
</div>

阶段 3 · Keyed For

<For> 按 key 复用节点、每个元素独立 Owner；删除元素时级联清理其 Effect。key 与 render 的 lambda 参数类型都可省略——从 each 推断。

<ul>
    <For each={users} key={(u) => u.id}>
        {(u) => <li>{u.name}</li>}
    </For>
</ul>
元素类型推断支持 signal 变量、普通 := 变量和函数返回值；若写了显式注解如 (u user)，则以注解为准。

阶段 4 · GUI 调度与生命周期

应用入口把「叶子聚合 effect」与「结构插槽接线」封装进 app.render：open(cfg) 先建好窗口外壳，render(() => <App/>) 在根 Owner 下建树、画首帧并在内部接好响应式——分支/列表切换重建子树后自动画一帧；Signal.batch 合并同一轮多次写入为一次重绘；app.close 销毁根 Owner，级联清理组件 onCleanup 与所有订阅。

app, err := gxapp.open({ title: "Gox", width: 800 })
if err != nil { panic(err) }
defer app.close()
app.render(() => <div>{...}</div>)  // 根 Owner 下建树 + 内部响应式接线
Signal.batch(() => { count(5); visible(false) })  // 一次重绘

有状态组件（SolidJS 风格，推荐）

组件函数只在建树时执行一次——状态是组件「自己的」，写在组件内部而非 main 里，靠 signal + effect 保鲜。副作用用 Signal.onMount 启动、Signal.onCleanup 清理，二者归属 app.render 建立的根 Owner，app.close 时级联执行。完整可运行示例见 examples/jsxapp-solid.gx（组件内定时器自增，close 时打印 unmounted）。

pub func Counter(props gxscene.Props) *gxscene.Instance {
    signal count = 0   // 组件局部状态
    let doubled = Signal.computed(() => count * 2)
    Signal.effect(() => { fmt.println("tick", count, doubled) })  // 状态变化逻辑
    stop := make(chan struct{})
    Signal.onMount(() => {
        go func() { /* 定时器里 count += 1 */ }()
    })
    Signal.onCleanup(() => { close(stop); fmt.println("unmounted") })  // close 时触发
    return <div>{count} / {doubled}</div>
}
app.render(() => <div><Counter/></div>)  // 根 Owner 在此建立
app.close()  // 级联执行 Counter 的 onCleanup
组件内直接用裸 count 读 signal（编译器补 ()）；onCleanup/onMount 必须写在组件函数体内（建树时注册到 Owner），这样卸载才能级联清理。

五、约束清单

  1. 标识符小写书写：GX 源码的函数/方法/字段一律小写，编译器还原；全大写缩写写大写原样保留。类型名例外：gxscene.Props / gxscene.Instance 按真实拼写大写开头、原样保留。
  2. signal API 大写前缀：Signal.computed / Signal.effect / Signal.createRoot / Signal.batch 等一律大写 Signal.，避免与 signal 声明关键字混淆；不要写裸 computed(...)。
  3. 回调用箭头函数：Signal.computed(() => expr) / Signal.effect(() => ...)，多语句用 () => { ... }，从 body 反推类型（含单点 signal getter），不写 func() T { return ... }。
  4. 组件名大写开头：pub func Stat(...) + <Stat/>；组件标签不能小写。
  5. 配置写裸对象字面量：gxapp.open({ ... })（只收配置，返回 App），从签名推断具名类型，不手写 gxapp.windowConfig{...}。
  6. pub 声明小写 + JSX 标签大写：pub func card 配 <Card/>；组件标签小写会被当成原生标签。
  7. Props 用 getter 保鲜：gxscene.get[T](props,...) 得到 getter，在插槽里 value() 读；写成 value 会变成不更新的快照。
  8. 组件只建树一次：函数体是「建树」而非「每次渲染」，不要在组件函数里放依赖刷新的副作用。
  9. 分支 selector 必须读 signal 才有响应式；<For> 必须提供 key 才能做 keyed 复用。
  10. Owner 作用域：effect / cleanup 归属当前 Owner，父销毁级联子；需要独立生命周期时用 Signal.createRoot。
  11. 结构变化重绘：app.render(() => <App/>) 内部已接好响应式，分支/列表切换自动重绘一帧，无需手写 bindReactive。
  12. 相等性裁剪：signal 默认 DeepEqual，相同值不触发；需要自定义比较用 Signal.newWithEquals。
