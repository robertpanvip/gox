一、书写约定（最先要遵守）

Gox 的设计是：转译器不读第三方包符号表、不做类型推导，只对小写形式做机械首字母大写还原（upperFirst）。因此行为完全可预测。你在 .gx 里写小写，生成的 Go 自动变大写。

GX 源码（你写的）生成的 Go规则
fmt.println()fmt.Println()包级函数：小写书写，还原
req.method / u.pathreq.Method / u.Path结构体字段：小写书写，还原
r.URL / http.StatusOK原样保留全大写缩写：写大写，不动
gxscene.get[T]()gxscene.Get[T]()runtime 符号：小写书写，还原
view.bindReactive(signal.effect)view.BindReactive(signal.Effect)方法：小写书写，还原
gxapp.open(view, gxapp.windowConfig{...})gxapp.Open(view, gxapp.WindowConfig{...})多词符号：只首字母小写，其余照抄
pub func card + <Card/>func Cardpub 声明小写；JSX 标签必须大写
三条边界（踩过的坑）：① 多词符号只小写首字母——windowConfig → WindowConfig，写成 windowconfig 会生成拼错的 Windowconfig。 ② Signal 是语法糖占位包名，必须大写开头：写 Signal.computed(...)，不要写裸 computed(...)（裸标识符不会被还原）。 ③ JSX 标签首字母大写 = 组件、小写 = 原生 HTML 标签，这是硬编码判定，组件标签不能小写。

二、工作原理（三段流程）

① 编译期

GX 源码（小写）
<div>
  <Card title={t}/>
</div>
↓
opcode 模板（静态骨架）
OpElem   "div"
OpComp   "Card"  Slot:0
OpClose

② 建树期（一次）

动态插槽 → getter
props["title"] =
  func() any { return t() }
↓
组件嫁接
调用一次 Card(props)
递归建出常驻子树

③ 更新期（每次写入）

signal 写入
t = "new"
→ effect 重跑
↓
精确写节点
只写依赖它的插槽
不重建整树，无 Diff
组件是一种「不透明的子树插槽」：骨架编译期固定，组件形状运行时嫁接；更新靠 getter 保鲜 + 递归透传，而不是重建整树或做 vdom Diff。

三、完整实战（一条龙）

下面这段是经过 go run 实测的完整 GX 源码，同时用到了对象字面量、对象解构、signal、条件分支、Keyed For 和应用入口——全部小写写法。

demo.gx · 编译：gox build demo.gx -jsx=scene -o main.go && go run .package main

import (
    gxscene "github.com/robertpanvip/gox/runtime/scene"
    gxapp   "github.com/robertpanvip/gox/runtime/app"
    "github.com/robertpanvip/gox/runtime/signal"
    "fmt"
)

type user struct { id int; name string }

// 叶子组件：pub 小写声明；从 Props 取 getter，在插槽里 value() 读当前值
pub func stat(props gxscene.props) *gxscene.instance {
    label := gxscene.get[string](props, "label")
    value := gxscene.get[int](props, "value")
    return <div class="stat"><span>{label()}</span><b>{value()}</b></div>
}

func main() {
    // 新特性：对象字面量 + 对象解构
    cfg := { title: "Gox", width: 800, height: 600 }
    { title, width } := cfg

    // signal 源 + computed 派生（count 变化 → doubled 自动重算）
    signal count = 0
    signal visible = true
    signal users = []user{{1, "Tom"}, {2, "Jack"}}
    doubled := Signal.computed(func() int { return count() * 2 })

    // 组合根视图：JSX 标签大写 = 组件；插值 {count} 编成 getter
    view := <div id="app">
        <h1>{title}</h1>
        if visible {
            <Stat label="count" value={count()}/>
            <ul><For each={users} key={(u) => u.id}>{(u) => <li>{u.name}</li>}</For></ul>
        } else {
            <b>Hidden</b>
        }
    </div>

    // 应用入口：gxapp.open / windowConfig 小写书写；app.close 同理
    app, err := gxapp.open(view, gxapp.windowConfig{ Title: title, Width: width, Height: cfg.height })
    if err != nil { panic(err) }
    defer app.close()

    // 一行接线：signal 写入 → 精确更新插槽 → 结构变化自动重绘
    app.bindReactive(signal.effect)

    // 批处理：同一帧内 count→5、visible→false，只重绘一次
    signal.batch(func() { count(5); visible(false) })
    fmt.println(doubled())  // 10
}
实测输出要点：初始渲染出 "Tom"/"Jack" 列表；visible=false 后条件分支切到 Hidden；doubled() 得到 10。<For> 的 render 参数 (u) 未写类型——编译器从 each={users} 的 []user 自动推断出元素类型。

四、响应式 UI 四阶段增强

阶段 1 · Owner / Cleanup / Effect 句柄

signal.effect 返回可销毁句柄，挂在 Owner 树下；父 Owner 销毁会级联停掉子计算并执行清理。写副作用时把清理登记在 effect 内，重跑前与销毁时都会执行。

signal.createRoot(func(o *signal.owner) {
    h := signal.effect(func() {
        fmt.println(count)
        signal.onCleanup(func() { /* 重跑前 / 销毁时执行 */ })
        signal.onMount(func() { /* 首次挂载执行一次 */ })
    })
    _ = h  // h.dispose() 幂等：断依赖、停订阅、执行清理
})
// 相同值不触发下游；自定义比较用 signal.newWithEquals
// 派生需要提前销毁时用 Signal.computedWithHandle
signal 源信号默认用 reflect.DeepEqual 做相等性裁剪——值未变不触发下游。scene.computation 是 signal.computation 的类型别名，因此 signal.effect 可直接作为 bindReactive 的实参。

阶段 2 · 条件分支

JSX 内支持 if / else if / else 子节点。selector 读 signal 登记依赖；索引变化时销毁旧 Owner、重建局部子树，索引不变时只更新叶子。

view := <div>
    if visible {
        <span>{count}</span>
    } else if other {
        <i>other</i>
    } else {
        <b>Hidden</b>
    }
</div>

阶段 3 · Keyed For

<For> 按 key 复用节点、每个元素独立 Owner；删除元素时级联清理其 Effect。key 与 render 的 lambda 参数类型都可省略——从 each 推断。

<ul>
    <For each={users} key={(u) => u.id}>
        {(u) => <li>{u.name}</li>}
    </For>
</ul>
元素类型推断支持 signal 变量、普通 := 变量和函数返回值；若写了显式注解如 (u user)，则以注解为准。

阶段 4 · GUI 调度与生命周期

应用入口把「叶子聚合 effect」与「结构插槽接线」合并：bindReactive 在分支/列表切换重建子树后自动画一帧；batch 合并同一轮多次写入为一次重绘；close 销毁时级联清理所有订阅与 Owner。

app, err := gxapp.open(view, gxapp.windowConfig{ Title: "Gox", Width: 800 })
if err != nil { panic(err) }
defer app.close()
app.bindReactive(signal.effect)
signal.batch(func() { count(5); visible(false) })  // 一次重绘

五、约束清单

  1. 标识符小写书写：GX 源码一律小写，编译器还原；全大写缩写写大写原样保留；多词符号只小写首字母（windowConfig 非 windowconfig）。
  2. Signal 占位名大写：Signal.computed / Signal.effect，不要写裸 computed(...)。
  3. pub 声明小写 + JSX 标签大写：pub func card 配 <Card/>；组件标签小写会被当成原生标签。
  4. Props 用 getter 保鲜：gxscene.get[T](props,...) 得到 getter，在插槽里 value() 读；写成 value 会变成不更新的快照。
  5. 组件只建树一次：函数体是「建树」而非「每次渲染」，不要在组件函数里放依赖刷新的副作用。
  6. 分支 selector 必须读 signal 才有响应式；<For> 必须提供 key 才能做 keyed 复用。
  7. Owner 作用域：effect / cleanup 归属当前 Owner，父销毁级联子；需要独立生命周期时用 signal.createRoot。
  8. 结构变化重绘：app 场景用 app.bindReactive(signal.effect) 接线，分支/列表切换才会自动重绘一帧。
  9. 相等性裁剪：signal 默认 DeepEqual，相同值不触发；需要自定义比较用 signal.newWithEquals。
